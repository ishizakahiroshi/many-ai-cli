# 看板（MCP ボード）への進捗の書き込み

> 最終更新: 2026-11-12 — 要約に書かれたコミットの番号から、push 済みのコミットのページをリンクにする、を追加。前回: 2026-11-11 — 作業の題名を最初の要約から付ける・要約に書かれた計画の下へ作業を並べる・成果の URL を出来事のリンクにする、を追加。クエリやフラグメントの付いた URL は欄として扱わないことを追記
> 2026-11-06 — 初版

many-ai-cli で動かした AI の作業を、MCP で書き込める看板（例: Many Iris の看板）へ自動で載せる機能です。**設定ファイルを置いた人だけが使う機能**で、置かなければ何も起きません。

## 何が載るか

送ってよいと指定したリポジトリの中で始めたセッションごとに、看板へ作業の項目を作ります。

1. セッションが始まったとき: 項目（種類 `task`、状態 `in_progress`、題名は「AI の名前: セッション名」）と、「開始」の出来事
2. AI が作業を1回終えるたび（完了マーカーの要約が届いたとき）: 要約を `note` の出来事として追加。最初の要約が届いたときに、項目の題名を「月-日 AI の名前: 要約の最初の1文」に付け直します
3. セッションが終わったとき: 状態を `done` にし、「終了」の出来事

指定していないリポジトリのセッションは送りません。お試し用の環境（trial）でも送りません。要約と題名は、秘密に見える文字列を伏せてから送ります。

## 作業を計画の下に並べる

AI は、完了マーカーの要約の後ろに、次の2つを足せます（many-ai-cli が AI に配る案内に入っています。書くかどうかは AI が決め、分からないときは書きません）。

```text
計画: docs/plan_list-order.md
成果: https://github.com/example/repo/pull/12
```

| 欄 | 書くもの | 看板で起きること |
|---|---|---|
| `計画:` | どの計画の分の作業か。リポジトリのルートからの相対パスか、https の URL | 看板の項目のうち、原本（`source_ref`）が同じものを探し、作業の項目をその下に入れます |
| `成果:` | PR やコミットの https の URL | その要約の出来事のリンクになります |

- **計画の項目が看板にまだ無いとき**: 書かれたパスが、リポジトリの中にある Markdown のファイル（`.md`）なら、計画の項目を作ります。題名はそのファイルの最初の見出し（`#` と先頭の `[状態]` を除く）で、ファイルの中身は送りません。案件の項目（種類 `project`）が1つだけあれば、その下に入れます。パスが実在しない・Markdown でない・URL で一致が無いときは、項目を作らず、作業は親なしのまま載ります（看板の項目は消せないので、書き間違いから項目を作りません）。
- **途中で別の計画に移ったとき**: 要約に別の計画が書かれると、そこまでの作業の項目を `done` にして、続きを新しい項目（`session/<番号>/2`、`/3`…）に載せます。計画ごとに、その計画でやった作業が並びます。計画が書かれていない要約は、直前の項目に入ります。
- **計画が一度も書かれなかったとき**: 作業は親なしのまま載ります。Many Iris の看板では「まだ結ばれていない作業」にまとまります。
- **AI が計画を間違えて書いたとき**: 出来事は別の項目へ移せませんが、項目の親は直せます。鍵を持つ AI に「`session/<番号>` を、この計画の下へ付け替えて」と頼んでください（`board_upsert_item` に `item_id` と `parent_id` を送る操作です）。
- パスは `\` 区切りやフルパスで書かれても、リポジトリの中なら相対パスに直して扱います。リポジトリの外・`..` を含むパスは、計画として扱いません。
- **`成果:` を書かなかったとき**: 要約の文にコミットの番号（7 文字以上。例「0a1b2c3d を push しました」）が書いてあり、そのコミットが GitHub の `origin` の branch に入っていれば、そのコミットのページをリンクにします。まだ push していないコミットにはリンクを付けません。文に番号が無いときは、リポジトリの先頭のコミットを推測で付けることはしません（同じリポジトリで別のセッションが動いていると、別のセッションのコミットになるため）。番号は 1 つの要約につき 3 つまで、書かれた順に確かめます。
- **URL がリンクにならないとき**: `計画:` と `成果:` の URL は、`?` から後ろ（クエリ）や `#` から後ろ（フラグメント）が付いているもの、秘密に見える文字列を含むものを、欄として扱いません。その URL は要約の文の中に残り、文と同じように伏せてから送られます。PR やコミットのページの、何も付いていない URL を書いてください（例: `https://github.com/example/repo/pull/12#issuecomment-1` はリンクにならず、`https://github.com/example/repo/pull/12` はなります）。

## 設定

many-ai-cli のデータフォルダ（`config.yaml` と同じ場所。既定は `~/.many-ai-cli/`）に `board.json` を置きます。

```json
{
  "schema_version": 1,
  "url": "https://board.example.com/board/mcp",
  "key_file": "C:\\keys\\board-writer.key",
  "repos": [
    { "path": "C:\\work\\my-app", "project": "my-app" },
    { "path": "C:\\work\\worktrees\\my-app", "project": "my-app" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `url` | 看板の MCP の住所。`https` のみ（`http` は `127.0.0.1` / `localhost` だけ）。`?` 以降や利用者名入りの URL は受け付けません |
| `key_file` | 書き込み用の鍵を1行だけ書いたファイルの絶対パス。送るたびに読み、`Authorization: Bearer` で送ります。鍵そのものを `board.json` や `config.yaml` に書かないでください |
| `repos` | 送ってよいリポジトリ。`path` の中（その下のフォルダを含む）で始めたセッションだけを送ります。`project` は看板に出る案件名で、省略するとフォルダ名になります。worktree を使う場合は、その置き場も足してください |

設定ファイルは書き込みのたびに読み直すので、編集した後に Hub を再起動する必要はありません。設定の誤り、鍵が読めない、看板が書き込みを断った、といった問題は Hub のログに警告として残ります（鍵の値はログに出しません）。

## 看板側の条件

看板は MCP の `tools/call` で次の3つの道具を受け付ける必要があります（Many Iris の看板の口と同じ形です）。

- `board_upsert_item`（`item_id`・`project`・`kind`・`title`・`state`。計画に結ぶときは `parent_id`、計画の項目を作るときは `source_ref` も送ります。既にある項目へは、変える欄だけを送ります）
- `board_add_event`（`item_id`・`kind` が `session_start` / `note` / `session_end`・`text`。成果の URL があるときは `ref`）
- `board_list`（`project`・`since_seq`。項目の一覧を読むために使い、出来事は読みません）

`board_list` に答えない看板でも、開始・要約・終了は今までどおり載ります（計画の下に並べることだけが働きません）。

項目の ID は `session/<many-ai-cli のセッション番号>` です（途中で計画が変わった分は `session/<番号>/2`…）。Hub を再起動した後に同じセッションが続いても、看板にある続きの項目へ書き足し、付けた題名は変えません。

## 止めるとき

`board.json` を消すか、`repos` から外します。看板に書いたものは、看板側の決まりに従って残ります。
