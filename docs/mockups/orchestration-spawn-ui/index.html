オーケストレーション spawn UI モック（v7）

確定した流れ: 起動フォームは通常通り（provider・モデル・cwd・ラベル・表示先 = この起動するセッション自身＝conductor の設定）。その下に、既存の設定パネルと同じ見た目のアコーディオン「▶ 子役割の詳細設定（任意）」を追加する。既定は閉じたまま（軽量・AI任せ）。開くと役割ごとにCLI＋モデルを事前指定でき、詳しく決めたい人にも対応する。

S-01 ツールバーへの「オーケストレーション」ボタン追加

⏻
▦
+ 新しいセッション
既存の並び「停止／grid」はそのまま。その右隣に、既存アイコンボタンと同じ丸枠スタイルで「オーケストレーション」を追加（ホバーで data-tooltip 表示）。クリックすると S-02 の起動フォームが開く。

S-02 起動フォーム + 詳細設定アコーディオン（閉）

[プロバイダ選択: Claude Code ▾]（このセッション＝conductor自身の設定）
[モデル選択欄]（conductor自身が使うモデル）
[作業ディレクトリ入力欄]
[ラベル（省略可）／表示先]（既存のまま）
▶子役割の詳細設定（任意） 未設定（AIが都度判断）
[キャンセル]
[起動]
既定はこの状態（閉じたまま）。conductor自身のprovider/モデルは通常の起動フォームの項目がそのまま使われるので専用UIは不要。子セッションのCLI/モデルは、閉じたままなら起動後にAI(conductor)がその都度判断する（v1〜v6で検討した完全自律案に戻る）。

S-03 詳細設定アコーディオン（開）

▼子役割の詳細設定（任意）
役割CLIモデル
実装役 Claude Code▾ Sonnet 5▾
テスト役 Codex▾ gpt-5-codex▾
レビュー役 使わない▾ —
+ 役割を追加 行を増やして役割を追加できる（初版は3行が既定、増減は任意）
ここで決めた役割は conductor に伝わり、以後 AI はこの対応表を優先して子を生成する。空欄の役割はAI任せになる。
Settings パネルの「▼ ログ設定」等と同じ開閉パターン。展開すると行ごとにCLIとモデルの2項目を選べる、通常のセッション起動フォームと同じ情報量を役割単位で持たせる。使わない行はCLI列を「使わない」にすればよく、モデル列は自動でグレーアウトする。

S-04 起動後の conductor セッション

#3 Claude Code — PlainSheet　conductor
[many-ai-cli] このセッションは orchestration conductor です。 [many-ai-cli] 役割マッピング（詳細設定あり）: 実装=Claude Code/Sonnet 5・テスト=Codex/gpt-5-codex・レビュー=未設定 [many-ai-cli] （詳細設定を開かなかった場合は「役割マッピングは未設定。子が必要なら都度 provider/model を判断してください」という案内になる） > このプロジェクトの機能追加を進めてください
S-02のまま起動した場合と、S-03で詳細設定した場合とで、instruction file への注入内容が変わる。どちらのケースでも conductor 自身の provider/モデルは起動フォームの通常項目でそのまま決まっている。

S-05 セッション一覧（子が自動出現）

#3 Claude Code — PlainSheet conductor
#7 Codex（gpt-5-codex）— テスト役 テスト役
詳細設定があればその通りのCLI/モデルで、無ければAIがその場で選んだCLI/モデルで子が生成される。どちらの経路でも見え方（親子ロールチップ）は同じ。
