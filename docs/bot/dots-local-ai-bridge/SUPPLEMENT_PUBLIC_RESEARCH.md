# #5 C1追加指示：公開情報・実践事例による方式比較の補強

## 目的と現在地

対象はGitHubリポジトリ many-ai-cli、案件番号は `#5 many-ai-cli dots-bridge-c1-20261003`。Slack案件番号とPR番号は別物。同じ#5のC1追加調査であり、新しい実装案件ではない。

ローカルAIとdotsが、依頼・質問・停止・回答・続行・完了を、人の取り次ぎなしで交換できる方式を選ぶ。製品仕様に加えて、公開された実践例・失敗例・既製の仕組みを調べ、少ない構成で実現できる候補と阻害条件を探す。

現在の成果はdevelop向けDraft PR #8、作業ブランチ `docs/dots-bridge-c1-comparison-20261003`、確認済みhead `755db76e6823d75920b526d62e014ceb712fafd7`。独立文書レビュー合格の報告あり。実ブラウザ表示QAは未実施。オーナーは手元のHTMLを開いたが、全表示項目の検収完了とは扱わない。C2接続実験は未着手。

元の実行指示・レビュー指示は、このディレクトリのINSTRUCTIONS.mdとREVIEW.mdを読む。本補足は調査範囲と成果物を追加し、実行権限をC2へ広げない。衝突する場合は独断で進めず同じSlackスレッドへ質問する。

## 許可範囲

- 公開情報の読み取り調査、資料の作成・更新、必要な生成索引の更新、文書のcommit/push、既存Draft PR #8の更新、独立文書レビュー。
- 元の7候補を比較し、有力な追加候補があれば加えてよい。現在の第一候補MCP tools＋MCP Events＋永続キューは仮置き。根拠によって順位を変更できる。
- ソース変更、テスト変更、依存追加、workflow変更、認証情報の取得・保存、新規アプリ・Webhook・pluginの登録、外部への試験送信、Hub/CLIの起動・再起動、常設監視、C2実験、merge・main push・releaseは含まない。
- 公開記事の読み取りにログイン・有料契約・アカウント設定が必要なら、取得できない範囲として記録する。制約の回避は行わない。

## 調査対象と方法

公式仕様・公式サンプル、X、Zenn、Qiita、note、技術ブログ、公開GitHubを対象とする。日本語・英語で検索し、検索日・検索語・対象媒体・採否を検索記録へ残す。取得不能や有力事例なしも記録し、全インターネットを網羅したとは主張しない。

対象はdotsの外部連携とイベント起動に加え、ローカルAI/CLIを外部イベントで起こす運用、AI間の質問と回答・続行、停止中の保存・再送・重複防止、Slack/GitHub/MCP/HTTP/A2Aによる連携。既製の中継・ワークフロー製品が受信・保存・起動・返信をどこまで担えるかも調べる。人気だけを採用理由にしない。

新しい事例を優先しつつ、仕組みの根拠として有効な過去事例も含める。転載・同じ元記事の紹介を独立した複数事例に数えない。Xは発見の入口とし、可能なら元記事・公開コード・公式仕様まで辿る。検索結果の断片だけで成功を断定しない。

事例ごとに次を整理する。

- URL、著者または公開元、公開日・更新日・調査日。日付不明は不明と記載。
- 製品名・版・実行環境・認証方式・必要権限・常駐場所・費用。記載がない項目を推測で埋めない。
- 通信の実際の経路、誰が相手を起こすか、質問後の再開能力、PC停止・切断時の保存と復旧。
- 証拠水準：公式仕様、公開コード/サンプル、著者の実測報告、提案のみ、こちらで未確認。成功報告と自分たちの実測を区別する。
- 今回の7候補のどれに対応するか、必要なアダプター、適用できる部分と未確認の部分。
- 成功条件・失敗例・制約。dots以外のエージェントの成功例を、dots対応の証拠にはしない。通常MCP通知をMCP Events製品統合と同一視しない。

有力事例は目安5～10件まで深掘りする。数合わせはしない。各媒体に検索を広げた後、追加の事例で候補・制約・順位が変わらなくなったら終了し、調査範囲と残る穴を示す。アクセス制約や新しい方式が見つかった場合は看板へ記録する。

## 成果物

すべてこのディレクトリのGit追跡文書へ保存する。公開資料へ秘密値・実データ・オーナーの私用パスを含めない。

1. PUBLIC_RESEARCH.md：検索記録、出典一覧、有力な実践例、失敗/制約、採用しなかった事例と理由、調査限界。
