## Original demonstrated source gaps (review snapshot)

### G1. Relay has a CLI caller but no Hub implementation/composition

Priority: completion-blocking feature gap. Contracts: K01, K02, K10; A01, A02, A11.

Go: `internal/hub/orchestration.go::handleSessionAPI` dispatches to `internal/hub/relay_api.go::{handleRelayGet,handleRelayStart,handleRelayStop,handleRelayResume,handleRelayCleanup}`. These implement GET and POST `/api/sessions/{id}/relay`, plus POST `relay-stop`, `relay-resume`, and `relay-cleanup`. The underlying fixed-source relay state/worktree/persistence code is in `internal/hub/relay*.go`.

Rust: `application/orchestrate_cli.rs::relay_plan` emits `relay` and `relay-stop` requests; the conductor prompt also advertises them. `hub/child_control.rs::is_control_route` admits only `send-child`, `inject`, and `children`. Neither `hub/router.rs` dispatch nor `needs_owned_request` nor `guard_methods` contains the relay branches. There is no relay state-machine implementation in `rust/src/orchestration` or a relay owner in `HubComposition`. An ordinarily authenticated valid relay request therefore falls through to the generic 501 `migration_unimplemented` response. Protocol `RelayStatus` and `SessionObservation::Relays` types are not producers: no application caller publishing `SessionObservation::Relays` was found. The five historical dynamic-operation rows correctly remain unresolved.

Existing tests: `application/orchestrate_cli/tests.rs` tests relay CLI behavior using supplied HTTP replies, not the actual Hub. `hub/child_routes/tests.rs` exercises real child admission/inject/children, not relay. No relay Hub/state-machine caller test exists in the reviewed source.

Required closure: implement the fixed Go relay behavior using the existing core, admission, board/worktree, process and task owners; connect all five branches and session relay observations. Add actual CLI→Hub and synthetic progress/exit/recovery tests, including per-unit DONE counters, review verdict/evidence, strong-review transition, stale child exit, headless one-process-per-instruction/no nudge, stop/resume/cleanup, persistence/restart and safe worktree cleanup. This is substantial unfinished implementation, not an optional-service 503 or a native-only gate.

### G2. Trial mode does not disable native webhook/ntfy notification delivery

Priority: isolation blocker. Contracts: K12 and trial contract; A02, A12.

Go ordinary behavior: `internal/hub/settings_handlers.go::{handleNotifyConfig,handleNotifyTest}` plus `internal/notify` own backend delivery. Trial mode is a deliberate migration extension, so disabling trial delivery must not silently disable ordinary production notifications.

Rust: `application/main_program/serve.rs::HubComposition::new` unconditionally constructs `notify::Manager::new(config.notify, tasks, warning)` and supplies it to HTTP, security and event observers. `notify::Manager` has a native reqwest client and no runtime-root/trial delivery policy. `send_test`, `send_approval`, `send_done`, and `send_security` can reach `send`, which performs HTTP for configured webhook/ntfy backends. `Config` trial defaults only replace port/path settings. The `/api/notify-config` published callback and `ApplicationEventObserver` can update the manager with enabled notification settings again. `/api/notify-test` accepts a request-selected backend regardless of configured backend emptiness. Native web-push is separately trial-denied; that does not protect this notification transport.

Existing tests: `hub/notify_http_tests.rs::notification_test_cancels_on_http_waiter_loss_without_waiting_for_backend_timeout` deliberately uses a loopback backend with trial paths; it tests cancellation, not the absence of live delivery. `application/push/tests.rs::native_trial_refuses_host_delivery_and_abort_does_not_mark_success` covers web-push only.

Required closure: compose an explicit native-production versus injected-fixture delivery policy in the existing manager; trial default must reject before native network IO for test, event and security paths, including after a settings update. Retain opt-in synthetic loopback transport tests through explicit injection. Do not weaken production backend compatibility or send any real notification to validate the fix.

### G3. Unknown session suffixes skip the fixed Go prefix-dispatch ordering

Priority: protocol compatibility gap. Contracts: K02; A02.

Go `handleSessionAPI` checks token, then exactly two trimmed path parts, then positive integer ID, then action, and only recognized endpoint actions reach their method/Host/Origin/PIN guards. Rust preflight does that only for recognized metadata/spawn/confirmation/child-control suffixes. Unknown `/api/sessions/` paths go through the generic guard and eventually 501.

Concrete source-derived cases: with a valid token and allowed Host, `/api/sessions/not-an-id/unknown` should be 400 and `/api/sessions/1/unknown` should be 404; the reviewed Rust source falls through to 501. With a bad Host, Go still returns its path/ID error before Host; Rust returns the Host error first. `/api/session/` singular metadata already has a broad prefix boundary; do not replace it with a suffix-only check.

Existing nearby test: `hub/session_routes/tests.rs` checks `metadata_path("/api/sessions/x/unknown")` directly, but the router does not invoke that parser for the unknown suffix. This is a caller gap despite the parser fixture. `hub/provider_transport_tests.rs::provider_prefix_retains_source_path_method_and_auth_order` covers providers, not sessions.

Required closure: one source-faithful `/api/sessions/` prefix dispatch shared with recognized branches; add authenticated/missing-token, malformed shape, invalid ID, unknown suffix, wrong method and bad Host/Origin cases through actual preflight/transport.

### G4. Unknown distribution suffix narrows Go's arbitrary-method guard

Priority: smaller protocol compatibility gap. Contracts: K02/K07; A02/A08.

Go `internal/hub/provider_distribution_handlers.go::handleProviderDistributions` uses `s.guard(w,r,r.Method)` before 404 for unknown suffixes. Rust `hub/distribution_routes.rs::methods` instead lists GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS. An authenticated allowed-Host `TRACE /api/provider-distributions/unknown` (or a valid extension method) therefore yields Rust405 where fixed Go returns404. Bad-Host precedence also changes. No request was sent in this review.

Existing tests: `empty_keys_fail_before_decoding_and_none_is_real_absence`, `corrupt_pointer_and_tampered_rollback_return_errors_without_success`, `diff_is_real_candidate_and_corrupt_current_is_not_silently_empty`, and `rollback_reload_failure_restores_pointers_and_live_registry` exercise known actions, not this fallback.

Required closure: preserve the ordinary auth/Host/Origin/PIN guard while leaving unknown-suffix methods unconstrained, then return404. Add a focused router/transport regression; no real catalog fetch is needed.
