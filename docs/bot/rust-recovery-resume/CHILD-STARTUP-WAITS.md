## Baseline inventory

## Outcome
- Preserve product/Go budgets. In particular, the native version service has a 10 s budget, app-server RPC has 15 s, subscription test has 20 s, background auth has 2 s, bootstrap has 10 s, and launcher connecting has 120 s. These are not CI startup allowances.
- Separate fixture readiness, fixture lifetime, and post-cancel/drain/end assertions. Use existing positive receipts where available; replace fixed startup sleeps with explicit receipts. A generous finite harness watchdog is still useful for hangs. A shared 60 s readiness watchdog is a proposal to validate on CI, not an established sufficient bound. Coordinate shorter child lifetimes and outer operation watchdogs first.
- Native CLI cancellation already waits for both parent and descendant markers. Its reported Linux failure is the explicit early executor-completion branch, not expiry of its 20 s readiness watchdog. Widening that watchdog alone does not address this observation.
- App-server tests have an outer 20 s harness watchdog and an inner 15 s product operation budget. The reported Windows failure is inner-15s; increasing only the outer watchdog does not change it. Preserve the product boundary while making fixture stages observable or simplifying the synthetic protocol child.
- Picker first 20 s wait covers fixture output/exit and can be a longer test-only guard. The separate 100 ms pre-cancel sleep should become child readiness evidence. Its second 20 s wait is cancellation completion.
- `ProcessEvent::Started` proves OS process creation; it precedes Windows Job attachment/resume. It does not replace child-executed markers, protocol replies, or HTTP readiness.
## Proposal boundaries
No edits are proposed to product timer values, deadline start points, zero/no-deadline semantics, or Go idle/registration behavior. No blanket replacement of `Duration` literals or shared `STEP` constants. An early child exit, failed receipt, or missing marker remains a test failure. Readiness changes must preserve exact outputs, ownership identity, protocol ordering, and cleanup evidence. This is an implementation inventory, not a code review or a diagnosis of the CI failures.

## Coverage and validation limits

The scan covered timeout, sleep, deadline, readiness/started markers, ProcessPlan/ManagedProcess, native process creation and PTY paths in `rust/src` and `rust/tests`. Detailed rows cover native CLI version, subscription app-server/status, host picker/detached dispatch, process owners, wrapper startup/registration, native Windows spawn, launcher, wrapper PTY/headless, plus directly related fixture setup and in-process sequencing. Pure timestamp arithmetic, transcript parsing, mock-only timing tests, and unrelated HTTP/storage/network deadlines are not child-startup waits. Initial-prompt screen timers, Whisper/tray readiness, and Git operation deadlines are explicitly called out as product policies so a broad timeout search does not accidentally change them.

The baseline inventory is a source inspection. Only the changes listed in the applied-disposition table belong to this batch; other recommendations remain unimplemented. Native validation of the changed guards is still required, and this inventory does not establish the cause of any observed failure.
